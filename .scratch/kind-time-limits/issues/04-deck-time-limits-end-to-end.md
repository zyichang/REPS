# 04 — 牌组的 `time_limits`:从牌组文件一直到学习页

Status: ready-for-agent

## Parent

`.scratch/kind-time-limits/PRD.md`

## What to build

牌组文件可以在顶层(和 `deck` 同级)写 `time_limits`,按题型覆盖默认上限。选择题的评分线跟着上限按比例放大。

- **格式(ADR-0008):** 键是题型代号,值是分钟,可以写小数,必须大于 0、不超过 180。用了它的文件必须写 `reps: 2`;
  `reps: 1` 里出现时报错并提示;不认识的键、超出范围或不是数字的值,报错并带 YAML 行号。没写到的题型用默认值。
- **存储:** schema 升到 v5(走版本化迁移),牌组新增「上限覆盖值」(题型 → 分钟)。
- **重新导入:** 牌组信息(标签、meta、版本)照旧更新,同时写入覆盖值;牌组的 updated_at 照旧更新,
  所以改动会随云存储里的牌组文件同步到其他设备。云数据库不用改。
- **导出:** 有覆盖值才写 `time_limits`;用到 `kind` 或 `time_limits` 的牌组写 `reps: 2`。
- **学习页:** 上限 = 牌组覆盖值,没有就用默认值。选择题的简单 / 良好线是上限的 1/6 和 1/2,比如 2.5 分钟对应 25 秒和 75 秒。

## Acceptance criteria

- [ ] 解析:整数和小数都能解析;不认识的键、0、负数、超过 180、不是数字、出现在 `reps: 1` 里,都报错并带行号。
- [ ] 迁移:v4 的库升到 v5 后数据不丢,旧牌组没有覆盖值。
- [ ] 重新导入:改了 `time_limits` 的牌组再导入后,覆盖值更新,进度保留,牌组 updated_at 变化。
- [ ] 导出往返:覆盖值原样写回;只用了 `time_limits`、没有 `kind` 的牌组也写 `reps: 2`。
- [ ] 计时规则模块:覆盖值优先于默认值;评分线按比例放大(单元测试)。
- [ ] 学习页:设了 `choice: 2.5` 的牌组,选择题倒计时从 2:30 开始,过了 75 秒才变红。
- [ ] 模拟器上手动验证,结果记在本 issue 的 Comments 里。
- [ ] 完整桌面测试台通过,ArkTS 构建成功。
