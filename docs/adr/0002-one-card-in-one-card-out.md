# ADR-0002 · 导入一张就是一张:软件只负责显示与排期

- **状态**:已接受
- **日期**:2026-09-24
- **相关**:ADR-0001(来源格式)、`Quizify.ets`、`Importer.ets`、`StudyPage.ets`
- **取代**:ADR-0001 中「一条笔记 N 个挖空生成 N 张卡」的说法

## 背景

原先照搬了 Anki 的 note / card 两层模型:一条笔记里有 N 个挖空,导入时
展开成 N 张卡,每张只挖其中一个空、其余显示答案,各自独立排期。
实机验证过确实如此 —— 4 个 `+++` 区块导入后得到 `notes=4, cards=6`,
因为其中一条有 3 个挖空。

这带来两个问题:

1. **导入结果不可预期。**写 4 张卡,进来 6 张;卡组里的数字对不上源文件。
2. **职责混在一起。**软件既要排期,又要替用户「生成」卡片内容,
   而生成规则藏在解析器里,用户改不了也看不见。

## 决定

**导入进来一张,存下来就是一张,显示出来还是那一张。软件不生成卡片。**

1. 一个 `+++` 区块 = 一条笔记 = **一张卡**,挖几个空都一样。
2. **一张卡上所有的空同时考**:未揭开时全部显示为空,揭开时全部填上答案。
   不再有「第几个空」的概念。
3. 想让一句话产出三张卡,就在源文件里**自己写三张**。这是作者的决定,不是软件的。
4. 卡片只有**正面**和**反面**两个字段。**不设页码** —— 导入格式(Markdown / YAML)
   本来也不提供它,Quizify 规范同样明确不记录页码。
5. 算法的职责收窄到一句话:**只决定卡片什么时候出现**,不碰卡片长什么样。

## 理由

- **可预期性优先于聪明。**用户能数清源文件里有几张卡,就该在应用里看到同样的数字。
- **两个关注点分开。**内容由作者在源文件里决定,排期由 FSRS 决定,互不侵入。
  想换排期引擎不影响卡片;想改卡片不影响排期。
- **原先的理由不成立了。**按空拆卡的好处是「第三个空记不住可以单独复习」,
  代价是导入结果不可预期、且软件替用户做了内容决定。
  在一个以「导入整本书」为核心的应用里,可预期性更值钱。
- **作者手上本来就有全部表达力。**真要单独考一个空,写成三张卡即可,
  而且这样写出来的卡在文件里看得见、可版本控制、可再编辑。

## 实现

| 位置 | 改动 |
|---|---|
| `Importer.storeDeck` | 原 `cardCount = clozeCount > 0 ? clozeCount : 1` → 恒为 `1` |
| `Quizify.renderCloze` | 签名去掉 `ordinal`,改为 `(front, revealed)`,所有空一起挖 / 一起填 |
| `StudyPage` | `cardOrdinal` 改为 `cardBlanks`,顶部标签由「第 N 个空」改为「N 个空」 |
| `Quizify.clozeCount` | 保留,但只表示空的个数,不再决定卡片数 |
| `cards.ordinal` 列 | **保留,恒为 0**。不做 schema 迁移,卡片指纹 `hash(deck+title+ordinal)` 因此保持稳定 |

## 影响

- 同一份文件重复导入仍然幂等:指纹里的 ordinal 恒为 0,认得出「还是那张卡」。
- 历史数据若已按空拆过卡,ordinal > 0 的那些行会变成孤儿。本项目尚无真实用户数据,
  直接清库重导即可;将来若需要,写一条把 ordinal > 0 合并回 0 的迁移。
- `notes` 与 `cards` 现在是严格 1:1。暂不合表 —— 内容(notes)与排期单元(cards)
  在概念上仍是两件事,合并省不下什么,却会让将来支持「一份内容多种考法」变难。

## 实机验证(2026-09-24)

同一份 4 区块、其中一条含 3 个挖空的测试卡组:

| 项 | 改动前 | 改动后 |
|---|---|---|
| `notes` / `cards` | 4 / **6** | 4 / **4** |
| `cards.ordinal` 取值 | 0, 1, 2 | **仅 0** |
| 挖空卡正面 | `[____]、选择 和 循环`(只挖一个) | `[____]、[____] 和 [____]`(全挖) |
| 揭开后 | 当前空填上 | `顺序、选择 和 循环`(全填) |
| 顶部标签 | `完形填空 · 第 1 个空` | `完形填空 · 3 个空` |

桌面回归套件 8/8 全过(其中解析器 86 条、行内标记 42 条、schema 72 条)。
