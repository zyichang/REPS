# ADR-0004 · Anki 式多牌组结构,取消「当前卡组」

- **状态**:已接受
- **日期**:2026-10-14
- **相关**:`view/StudyTab.ets`、`view/StudyPage.ets`、`view/BrowserTab.ets`、`data/Schema.ets`(`SQL_DECK_COUNTS`、`SQL_BROWSE`)
- **取代**:学习页「一次只学一本书 + 去词卡表切换课本」的结构

## 背景

原来的结构是「当前卡组」:学习页只显示一本书,换书要去词卡表的 ⋯ 菜单里切。
用户发现这样做越来越像背单词软件(一次一本词书),而 REPS 的定位是 **Anki 类**
间隔重复软件:同时有多个牌组,任何一个都能直接点进去学。

## 决定

照 Anki 桌面版 / AnkiDroid 的结构重排学习与浏览两个标签页:

1. **学习页的根是牌组列表。** 每行一个牌组,各自显示 新 / 学习中 / 待复习
   (Anki 配色:蓝 / 红 / 绿,0 显示灰)。点一行进入该组的**概览**
   (原落地页:三段进度条 + 三个数字 + 开始学习),再进入作答。
   行尾 ⋯ 是清空进度 / 删除牌组;底部是导入。
2. **词卡表改为浏览器。** 卡组过滤(全部 / 某一组)+ 搜索(正面 / 背面 / 标题)
   + 卡片列表 → 预览 → 编辑;右上角 + 新建并选择牌组。
3. **没有「当前卡组」。** `currentDeckId` 及其持久化 key 删除。浏览器和统计页的
   卡组过滤只是查看视角,不影响学习页,也不持久化。
4. **「全部牌组」不再是一种学习模式**,只作为浏览器与统计页的过滤项。
   Anki 也没有「全部一起学」,它靠父牌组实现;REPS 的牌组目前是平的(见下)。
5. **每日上限对每个牌组各算一份**(Anki 默认预设的行为):新卡额度 20 时,
   每组各能出 20 张。仍是一套全局设置,暂不做按组的预设。
6. 页面栈用 **Navigation + NavPathStack**(学习页、浏览页各一个),返回 / 侧滑由
   Navigation 弹栈;只有「我的」还用 Index 的返回计数器。

## 为什么

- 用户的 PKB 本来就是多学科并行(数学、数据结构、电路……),每天各学一点,
  「先切换再学」的一步是纯摩擦。
- 牌组列表的计数用**一条分组 SQL**(`SQL_DECK_COUNTS`)+ 纯函数套上限
  (`applyDeckLimits`),与概览页的逐组查询在测试里逐列对拍(`deckcounts_test.ts`)。
  这是 CONTEXT 经验 7 的延续:同一个数只能有一个口径。
- 上限按组各算,结构上就满足经验 6(每个卡组的额度完全独立)。

## 没做 / 以后

- **嵌套牌组(`A::B`)**:暂不做,卡组保持扁平,也就不用迁移数据库。
  `SQL_DECK_COUNTS` 按 `deck_id` 分组,将来加 `::` 树时在列表层把子组计数汇总到父组即可,
  不需要改作答流程。
- **按牌组的选项预设**(各自的新卡额度、复习上限、算法):暂不做。
- 浏览器里**改已有卡片的牌组**(Anki 的 Change Deck)暂不做,只在新建时选牌组。

## 后果

- preferences 里会残留一个不再读取的 `current_deck_id`,无害。
- 学习页不再接收「去学习」这类跨标签跳转,`SK_GOTO_TAB` 已删除。
