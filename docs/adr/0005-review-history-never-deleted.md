# ADR-0005 · 复习流水永不删除

- **状态**:已接受
- **日期**:2026-10-14
- **相关**:`data/Schema.ets`(`SQL_ARCHIVE_DECK_LOGS`、`MIGRATE_ADD_ARCHIVED`)、`view/StatsPage.ets`、`devtest/history_test.ts`
- **取代**:CONTEXT.md 里「另需一张永不删除的『每日汇总』表」的计划

## 背景

原来删牌组、删卡、清空进度都会连带删掉 `review_log`。于是学完一本书删掉它,
花在上面的时间、打卡天数、热力图里的格子全都消失。用户的要求是:统计页上半段
(总作答、保持率、学习天数、连续天数、热力图、学习时长)**按整个应用算,与牌组无关**,
删掉的牌组也要算进去;清空进度也一样(时间是真实花掉的)。

## 决定

1. `review_log` **永不删除**。删牌组、删卡只删 notes / cards / scheduling。
2. 「清空进度」把该组流水标成 `archived = 1`,并删掉排期。综合统计照算;
   这个牌组自己的「今日已学」不再看已归档的流水,进度从零开始。
3. 旧库在 `Database.init()` 里按「列在不在」补 `archived` 列(`ALTER TABLE … ADD COLUMN`,
   默认 0),重复启动不会再跑。
4. 统计页分两段:**综合统计**(全部流水,含已删牌组)/ **进度统计**(按所选牌组,
   只看还存在的卡)。

## 为什么不做「每日汇总表」

原计划是另建一张按天汇总的表。但保持率需要逐条流水(排除每张卡的首答),
汇总表给不出来;既然流水本身要留着,再维护一张汇总表就是同一个数的第二个口径
(CONTEXT 经验 7)。卡片 id 是 AUTOINCREMENT,不会复用,所以孤立的流水不会被新卡「认领」。

## 后果

- 流水只增不减。按每天几百条估算,十年在几十万到百万行,SQLite 按 `ts` 有索引,可接受。
- 此前已经被删掉的流水找不回来。
