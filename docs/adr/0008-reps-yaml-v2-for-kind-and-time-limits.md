# ADR-0008 · 用到题型或时间上限的牌组写成 `reps: 2`

- **状态**:已接受(🚧 还没实现)
- **日期**:2026-11-02
- **相关**:`data/Yaml.ets`、`data/YamlExport.ets`、`docs/data-model.md`、ADR-0006
- **扩展**:ADR-0007(REPS Card YAML v1)

## 背景

题型功能给牌组文件加两个字段:卡片上的 `kind`(题型:`choice` / `blank` / `short` / `long` / `essay`)
和顶层的 `time_limits`(各题型的答题时间上限,单位分钟)。术语见 `CONTEXT.md`「题型」。

现在的解析器是严格子集:不认识的字段直接报错,`reps` 只认 `1`(`Yaml.ets` 的 `V1_TOP_FIELDS` 与 `reps` 检查)。

## 决定

1. 用到 `kind` 或 `time_limits` 的牌组写成 `reps: 2`。其余字段与 v1 完全相同。
2. App 同时读 `reps: 1` 和 `reps: 2`。`reps: 1` 的文件里出现 `kind` / `time_limits` 仍然报错,提示改成 `reps: 2`。
3. 导出写**够用的最低版本**:没用到新字段的牌组照旧写 `reps: 1`。

## 理由

- 旧版 App 读到 `reps: 2` 报「不支持的格式版本 reps: 2」,一看就知道该升级。
  如果新字段直接加进 v1,旧版报的是「不认识的字段 kind」,看起来像文件写坏了。
- 「写着 `reps: 1` 的文件,任何版本的 App 都读得了」这条保证不被打破。

## 未采纳

- **新字段直接加进 v1。** 省一个版本号,但旧版的报错会误导人,也打破上面那条保证。

## 后果

- **版本不一致的设备,同步会卡住。** 新版导出的 `reps: 2` 牌组,旧版下载后解析失败;同步一步失败就整轮重来,
  所以旧版那台的同步会一直失败,直到升级。2026-11 时只有开发者自己的手机和平板,一起升级即可。
- **正式发布的版本必须同时支持 `reps: 1` 和 `reps: 2`。**
- 牌组广场上的 `reps: 2` 牌组,旧版用户导入时会被提示升级。
